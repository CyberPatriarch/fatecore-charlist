# Fate Core — Анкеты персонажей

Локальное PWA для ведения динамических листов персонажей Fate Core. Позволяет создавать анкеты с произвольной структурой, сохранять их в браузере, обмениваться JSON-файлами и печатать красивые листы в PDF.

## Возможности

- **Динамическая структура.** Секции и поля можно добавлять, переименовывать, дублировать, удалять и менять местами — как в шаблоне, так и в отдельной анкете.
- **Предпросмотр шаблона.** В редакторе шаблона есть вкладка «Предпросмотр»: можно сразу увидеть готовый печатный лист с примером заполнения, не создавая персонажа. Оттуда же шаблон печатается как пустая или заполненная форма.
- **Оформление секций.** Для каждой секции выбирается стиль заголовка (цветная полоса, акцентная линия или строгий стиль) и один из четырёх цветов. В печати полоса тянется от края до края листа и чётко разделяет секции.
- **Шрифт и отступы.** Для каждой секции настраиваются размер заголовка и текста, шрифт с засечками или без, полужирное и курсивное начертание. Отдельно задаётся отступ после секции в миллиметрах — можно оставить пустое место для заметок от руки.
- **Типы полей:** короткий и длинный текст, число, трекер с кружками (обычный и со значениями), повторяемые группы. У трекера со значениями каждому кружку можно задать произвольное число, а не только последовательность 1, 2, 3.
- **Готовые пресеты:** навыки (название + уровень), трюки, последствия (описание + тяжесть).
- **Базовый шаблон Fate Core:** имя, раса, детали, обновление, концепция, проблема, три аспекта, титулы, 6 навыков, 3 трюка, физический и ментальный стресс, 3 последствия.
- **Варианты правил.** На основе шаблона можно собрать собственную анкету: ману, раздельные физические/ментальные/духовные последствия и любые другие поля.
- **Локальное хранение.** Данные лежат в IndexedDB браузера, без сервера и аккаунтов. Автосохранение с индикатором статуса.
- **JSON.** Экспорт и импорт персонажа, шаблона или полной резервной копии.
- **Печать / PDF.** Отдельный печатный вид с настройками: скрывать пустые поля, чёрно-белая печать, плотность. PDF сохраняется через системный диалог печати (A4).
- **PWA.** Устанавливается на устройство и работает офлайн после первого открытия.

## Стек

- React 19 + TypeScript + Vite
- React Router (`HashRouter` — работает на любом статическом хостинге без rewrite-правил)
- Dexie / IndexedDB
- Zod — валидация импортируемых файлов
- vite-plugin-pwa — манифест и service worker
- Vitest + Testing Library

## Запуск

```bash
npm install
npm run dev
```

Приложение откроется на `http://localhost:5173/fatecore-charlist/` (корень перенаправит туда же).

### Сборка и предпросмотр

```bash
npm run build
npm run preview
```

Готовые файлы — в `dist/`. Предпросмотр сборки: `http://localhost:4173/fatecore-charlist/`.

### Тесты

```bash
npm test          # однократный прогон
npm run test:watch
```

## Как пользоваться

1. На главной странице нажмите **«Новый персонаж»**, выберите шаблон и введите имя.
2. Заполняйте анкету — изменения сохраняются автоматически (статус виден в шапке).
3. Вкладка **«Структура»** меняет лист только текущего персонажа: можно добавить «Мана», трекер, дополнительные последствия и т. д.
4. Кнопка **«Печать / PDF»** открывает печатный вид. В диалоге печати выберите «Сохранить как PDF», формат A4.
5. **Шаблоны** редактируются отдельно. В редакторе шаблона переключитесь на вкладку **«Предпросмотр»**, чтобы увидеть лист до создания персонажа, проверить оформление секций и распечатать шаблон.
6. Внешний вид заголовков секций настраивается прямо в конструкторе: стиль «Цветная полоса», «Акцентная линия» или «Строгий стиль» плюс цвет — вино, бирюза, золото или графит.
7. Там же настраиваются шрифт, размеры заголовка и текста, полужирное и курсивное начертание. Поле **«Отступ после, мм»** добавляет пустое место между секциями — удобно для заметок от руки.
8. У трекера со значениями в конструкторе появляется список кружков: каждому можно назначить своё число. Пустое значение означает номер кружка по порядку.
9. Уже созданные персонажи хранят снимок структуры, поэтому изменения шаблона их не ломают.
10. **Экспорт JSON** — для обмена или ручного бэкапа. **«Резервная копия»** выгружает все шаблоны и анкеты одним файлом.

## Хранение данных

- Данные хранятся в IndexedDB текущего браузера и привязаны к origin (схема + домен + порт).
- Очистка данных сайта в браузере удалит анкеты — делайте резервные копии.
- Перенос на другой домен или браузер выполняется через экспорт/импорт JSON.
- Приложение не отправляет данные в сеть.

## Развёртывание

Приложение полностью статическое. Подойдёт GitHub Pages, Netlify, Cloudflare Pages, Vercel или любой веб-сервер. Текущая версия опубликована на GitHub Pages: **https://cyberpatriarch.github.io/fatecore-charlist/**

### GitHub Pages

Деплой автоматический. Workflow `.github/workflows/deploy.yml` запускается при каждом push в `main` (или вручную: Actions → «Deploy to GitHub Pages» → Run workflow). Он устанавливает зависимости через `npm ci`, прогоняет `npm test`, собирает проект и публикует `dist/` через GitHub Actions.

В настройках репозитория выбран источник **Settings → Pages → Source: GitHub Actions**. Ветка `gh-pages` не используется.

Так как project site живёт в подкаталоге, в `vite.config.ts` задан `base: '/fatecore-charlist/'`. После смены `base` проект нужно пересобрать. `HashRouter` не требует SPA-fallback, а манифест использует относительные `start_url` и `scope`, поэтому PWA работает внутри `/fatecore-charlist/`.

Для ручной публикации на другом хостинге достаточно выполнить `npm run build` и выложить содержимое `dist/`. Открывайте сайт по HTTPS (или `localhost`) — это требование для service worker и установки PWA.

## Структура проекта

```
src/
  domain/       модель полей, шаблоны, значения, предпросмотр, Zod-схемы
  storage/      Dexie, репозиторий, импорт/экспорт JSON
  hooks/        автосохранение
  components/   поля, редактор структуры, предпросмотр, печатный лист, модалки
  pages/        библиотека, анкета, редактор шаблона, печать
  ui/           кнопки, тосты, модальное окно
  styles.css    экранные, адаптивные и печатные стили
public/         иконки и favicon
```

## Ограничения MVP

- Нет облачной синхронизации и аккаунтов.
- Нет совместного редактирования.
- PDF формируется браузером через печать, а не отдельной библиотекой.
- Импорт не выполняет слияние: данные добавляются как новые копии с уникальными именами.
